# 第15组：六网格桥型扩展仿真

最终复测：`results/bridge_20260921_222016/acceptance.json` 为 PASS，
六物体6/6、桥型2/2。具体数据、视频索引及失败记录见 `桥型仿真复测结果.md`。

保留原六网格坐标、四个未替换方块、原红蓝分类位置及运动流程。
原 G2 红方块、G4 蓝方块替换为橙色桥型，合计两红、两蓝、两桥型。
桥型由一根横梁和两个支脚组成，外包络 40×40×40 mm，贯通孔宽 20 mm、高 28 mm。
Gazebo 使用三个独立碰撞盒构成同一刚体；质量 50 g，按组合体计算质心与惯量。
MoveIt 继续使用包含整个桥型的 40 mm 保守包围盒，不把镂空当作机械臂可通行空间。

新增橙色类别 HSV 范围及两个桥型放置槽；不改原有红蓝阈值。
桥型位置为 (-0.14, 0.125)、(-0.094, 0.164) m，原有红蓝槽保持不变。
第二槽位于左侧取物区边缘外，其附近网格 G4 在该桥型取走后已空；
保持原 65 mm 搬运中心高度，不以降低高度或放宽安全检查绕过可达性限制。
第一个桥型槽使用本场景中空闲的第三个红色槽位置；两只红块仅占前两个红色槽。
因此桥型仍放在左侧整理区，与真实系统桥型放左侧的规则一致。
这是颜色关联类别检测，不是颜色无关的形状识别，也不是实机 YOLO11。
抓取沿用原系统的对齐检查与固定约束辅助附着，不代表纯摩擦抓取动力学验证。

为处理首轮释放时的 Gazebo 崩溃，本副本将抓取检查、约束建立和解除排队到
Gazebo 物理更新线程执行，ROS 服务等操作实际完成后才返回结果。
未改动抓取对齐阈值、关节限位、碰撞判断或失败恢复标准。
侧视相机仅记录外观和过程，不给检测器、控制器或验收器提供类别信息。
本轮复测覆盖普通六物体场景；异常测试结果来自2026年9月14日版本。

本副本使用独立 WSL 编译目录 task3_bridge_ws_20260921、ROS 域95、Gazebo端口11395。
原 experiment3_sim_complete_20260914 及其历史结果未修改。

## 运行

在 Ubuntu 22.04 / ROS 2 Humble 环境执行：

```bash
bash 01_build.sh
python3 scripts/run_supervised.py
```

离线检查：在 ROS 环境运行 `python3 scripts/check_bridge_variant.py`。
录像和结果交叉核验：运行 `python3 scripts/verify_run.py results/具体目录`。
`python3 scripts/run_supervised.py --probe` 仅启动可达性诊断，不执行自动抓取。

每次产生独立 results/bridge_时间戳 目录。验收条件为六个物体全部正确、
其中两桥型全部正确，并通过既有运动安全检查。只有 acceptance.json 实际为 PASS
表示该轮通过。历史测试结果按各自版本单独记录。
