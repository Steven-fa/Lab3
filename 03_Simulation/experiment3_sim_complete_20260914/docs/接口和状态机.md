# 实验三接口与状态机

`config/sorting.yaml` 固定 6 个网格的物理中心与相机投影关系。检测框中心落入唯一网格时才关联目标；不通过相机估算任意空间抓取点。分类区由检测类别映射，每区具有三个不重叠落点。

控制器在 `WAIT_READY` 等待相机和机械臂服务；连续 4 帧稳定检测后进入 `OBSERVE`。空网格记录 `EMPTY`，不支持类别或低置信度记录 `UNKNOWN`，多物体框冲突记录 `AMBIGUOUS`。可执行目标进入 `SELECT` 和 `EXECUTING`，成功后 `VERIFY`，失败后 `RECOVER`。一轮所有网格已处理或没有可执行物体时进入 `DONE`。相机超时、长任务超时或不安全状态进入 `STOPPED`。

任务请求示例：

```json
{"job_id":"0123456789abcdef0123456789abcdef","grid_id":"1","class_id":"blue_cube","confidence":0.96,"bbox":[388,317,62,58],"bin_slot":0}
```

`job_id` 是 32 个小写十六进制字符，任务控制器自动生成。`grid_id` 必须存在于配置；`class_id` 必须有分类区；`bin_slot` 必须是分类区容量内的整数。识别与目标选择阶段不读取 Gazebo 真实类别。

接口每 0.5 秒发布心跳和当前阶段。一次只执行一个任务；未就绪或忙碌时拒绝新请求。重复 job_id 不会再次执行。结果包含同一 job_id、`ok`、`status`、预检和执行记录；错误结果还包含 `error`、`recovery`、`safe_to_continue`。

控制器的任务时限为 180 秒，超时发送取消并进入停止状态。接口具有额外的 195 秒看门狗。取消指向指定任务，工作进程保存底层 Action goal handle，取消当前轨迹后在条件允许时退回安全位。如果仍持有物体，则保持夹持并停止，不在空中释放。

运动顺序：

1. 确认物体仍在检测关联的固定网格，选择该物体为抓取插件目标。
2. 同步其他物体与桌面的碰撞模型，生成取物和放置的垂直逆解链。
3. 张爪、Home、到取物点安全高度、下降。
4. 闭爪并验证物体未被推走、对位误差和附着前后位置连续性。
5. 垂直抬升至物体中心 Z=0.065 m，沿基座前方的短圆弧转移。夹爪朝向随方位连续变化，逆解以前一点为种子，拒绝翻腕和关节跳变；执行前使用 MoveIt 检查附着物和沿途碰撞。
6. 到类别对应落点，下降至 Z=0.04 m、张爪、释放。
7. 核对物体最终位置，撤离并回 Home。

取物时允许夹爪与当前目标接触；其他物体继续保留在碰撞场景中。垂直链使用实际关节角差检查，避免跨 ±π 时把大幅跳变误判为小变化。

分类区的所有落点均处于基座前方（Y>0）。回零和接近使用单调的关节插值并逐段检查碰撞。转运高度下，方块底面名义高度为 45 mm，比桌上 40 mm 方块高 5 mm；修改方块尺寸或场景后须重新验证。

异常场景固定注入方式：G2 为绿色未知物体，G3 为空；G5 对逆解接口请求 `[1,1] m` 的不可达位置；G6 在闭爪步骤保持张开，由真实抓取检查拒绝附着。这些是明确记录的测试输入，不用来伪装正常任务结果。

验收监测单独读取场景真值及最终物体位置，计算正确分类数，并合并关节与物理接触监测结果。它不参与类别判断或选择抓取网格。
